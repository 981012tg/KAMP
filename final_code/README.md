# 예측에서 현장 조치까지: 이원화 모델 기반 제조공정 전력·자원 최적화

제6회 K-인공지능 제조데이터 분석 경진대회에 팀 `catch`가 제출한 제조공정 전력 예측 및 피크 저감 프로젝트의 최종 코드입니다.

매 정각을 기준으로 향후 24시간의 전력을 15분 간격 96개 값으로 예측하고, 전력값이 176 이상인 구간을 피크로 탐지합니다. 예측에서 끝나지 않고 오차와 피크 발생 조건을 분석한 뒤, 생산일정을 조정하여 최대전력과 비용을 낮추는 방안까지 연결했습니다.

## 프로젝트 목표

1. 향후 24시간의 15분 단위 전력값 예측
2. 전력값 176 이상인 피크 구간 탐지
3. 예측 오차와 피크 발생 조건 분석
4. 생산일정 재배치를 통한 최대전력 및 비용 저감안 탐색

## 데이터

원본 데이터는 [KAMP 인공지능 제조 플랫폼](https://www.kamp-ai.kr/)이 제6회 K-인공지능 제조데이터 분석 경진대회 참가자에게 제공한 제조공정 데이터입니다. 데이터의 이용 및 재배포 조건을 고려하여 이 저장소에는 포함하지 않습니다.

- 파일명: `okm_augumented_2021.csv`
- 수집 기간: 2021-01-01 ~ 2021-09-14, 총 257일
- 원본 크기: 시간 단위 6,168행, 18개 변수
- 전력 관측: 한 시간당 15분·30분·45분·60분 값, 총 24,672개
- 주요 변수: 날짜, 시간, 15분 단위 전력, 생산량, 날씨, 전기요금 및 인건비 관련 변수

## 분석 방법

### 데이터 분할과 재학습

- 학습 구간: 2021-01-15 ~ 2021-06-30
- 평가 구간: 2021-07-01 ~ 2021-09-14
- 매 정각 최근 전력·생산 이력, 1·2주 전 동일 시간대 정보와 향후 24시간 생산계획을 사용
- 미래 정보를 학습에 포함하지 않도록 시간순으로 분할하고 주 단위로 재학습
- Python, NumPy, PyTorch 난수 시드 42 고정

### 전력량 예측

가동 여부가 바뀌는 휴무·복귀 주에는 1주 전 값을 그대로 사용하는 기준선의 오차가 커졌습니다. 이를 보완하기 위해 현재 생산 상태와 1·2주 전 상태를 비교하는 규칙, 상태 전환 피처, 비가동 프로파일과 LightGBM 잔차 보정을 결합했습니다. 비교 모델로는 양방향 2층 GRU를 사용했습니다.

### 피크 탐지

큰 전력을 낮게 예측해 피크를 놓치는 문제를 줄이기 위해 분위수 LightGBM과 GRU를 학습했습니다. 최종 피크 탐지 모델은 LightGBM 65%와 GRU 35%를 결합한 앙상블입니다. 정식 경보 기준은 176이며, 현장 대응 시간을 확보하기 위해 164.5 이상 176 미만을 `주의` 단계로 추가했습니다.

## 주요 결과

### 전력량 예측 성능

7~9월 전체 예측 기준입니다. 값이 낮을수록 좋습니다.

| 모델 | MAE |
| --- | ---: |
| 1주 전 동일 시각 기준선 | 24.643 |
| GRU | 9.058 |
| 최종 LightGBM | **7.872** |

최종 LightGBM은 기준선 대비 MAE를 약 68.1% 줄였습니다.

### 피크 탐지 성능

고정 경보 기준 176을 적용한 7~9월 전체 예측 결과입니다.

| 모델 | 정밀도 | 재현율 | F1 | 오경보 | 미탐지 |
| --- | ---: | ---: | ---: | ---: | ---: |
| LightGBM | 0.606 | 0.789 | 0.685 | 9,904 | 4,074 |
| GRU | 0.578 | 0.802 | 0.672 | 11,294 | 3,816 |
| LightGBM 65% + GRU 35% | **0.619** | **0.803** | **0.700** | **9,529** | **3,793** |

8~9월 운영 분석에서는 정식 경보만 사용할 때 재현율이 0.852, 미탐지가 1,460칸이었습니다. 주의 단계를 함께 적용하면 재현율은 0.944로 높아지고 미탐지는 552칸으로 줄었습니다.

### 오류 및 영향요인 분석

- 비가동과 주말 구간은 전체 평균보다 오차가 작았습니다.
- 높은 생산량, 생산 종료 직후, 실제 전력 200 이상 구간에서 오차가 컸습니다.
- 실제 피크는 오전 9시, 높은 생산량, 생산량 급증 조건에서 자주 발생했습니다.
- 오경보의 94.4%는 실제 전력 150~175, 미탐지의 96.5%는 176~199에 집중되어 기준 176 부근의 작은 수치 오차가 판정 오류로 확대되는 경향을 확인했습니다.

### 생산일정 최적화 모의실험

예측 전력이 높은 시간의 생산량 일부를 월간 총생산량과 시간별 생산 한도를 유지하면서 다른 날짜·시간으로 이동했습니다.

| 기간 | 최대전력 변화 | 감소율 | 총비용 변화 | 절감률 |
| --- | ---: | ---: | ---: | ---: |
| 7월 분석 29일 | 210.33 → 190.63 kW | **9.36%** | 6,532 → 6,279만원 | **3.87%** |
| 8월 31일 | 209.93 → 192.53 kW | **8.29%** | 5,718 → 5,298만원 | **7.35%** |

이 결과는 실제 공장 운영 실험이 아니라 제공 데이터와 비용 가정에 기반한 모의실험입니다. 현장 적용 시에는 납기, 설비 능력, 품질 및 인력 조건을 추가로 확인해야 합니다.

## 실행 방법

검증 환경은 Windows, Python 3.12.10이며 CPU만으로 실행할 수 있습니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

1. `dataset/okm_augumented_2021.csv`를 준비합니다.
2. `00_KAMP_full_pipeline.ipynb`를 엽니다.
3. 위에서 만든 Python 환경을 Jupyter 커널로 선택합니다.
4. 커널을 다시 시작하고 위에서부터 `Run All`을 한 번 실행합니다.
5. 마지막 셀의 `전체 Run All 완료` 메시지를 확인합니다.

전체 파이프라인은 앞 단계의 결과를 다음 단계가 사용하므로 셀 순서를 바꾸거나 일부 셀을 건너뛰지 않아야 합니다. 검증 컴퓨터의 전체 실행 시간은 약 139.5분이었으며 컴퓨터 성능에 따라 달라질 수 있습니다.

실행 결과는 자동으로 `results/`와 `submission/`에 저장됩니다. 이 저장소에는 실행 코드만 공개하며 원본 데이터, 전처리 산출물, 모델 파일, 예측 CSV 및 생성 결과는 포함하지 않습니다.

## 재현성과 한계

- 날짜별 행 수, 시간 순서, 결측값, 음수값, 학습·평가 구간, 배열 크기와 저장 후 재로딩을 단계별로 검사합니다.
- 7~9월 결과를 일부 모델 설정과 주의 기준 선택에 참고했으므로 완전히 분리된 미사용 홀드아웃 평가로 해석할 수 없습니다.
- 원본에 전력 단위가 명시되지 않아 KAMP 가이드의 15분 최대수요전력 설명을 근거로 비용 계산에서 kW로 가정했습니다.
- 날씨 변수는 전력과의 관계가 작아 최종 입력에서 제외했습니다.
- 생산량만으로는 설비 구성과 가동 순서를 알 수 없어 생산 종료, 급격한 생산 변화와 드문 저녁 피크에서 오차가 커질 수 있습니다.
